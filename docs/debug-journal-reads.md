# 日志前缀的增量校验

`EventJournal.read` 保留每 stream 的跨进程读写锁，读取完整目录、manifest、
checkpoint 和全部事件文件，包含分页、通道或固定截点排除的尾记录。
私有权限、普通文件、单链接、短读、路径替换和大小预算由同一安全读取器核对。
每个文件的实际字节重新计算 SHA-256；mtime、inode 或 checkpoint 相同不足以
复用历史。

只有 manifest 原始字节、epoch 列表，以及全部旧文件名称和字节哈希一致时，
才复用已完成校验的前缀。新增记录继续核对分段范围、长度、哈希链、身份、
协商通道、顺序 epoch、恢复摘要、messageId 窗口与时钟。checkpoint 的索引、
尾哈希和总字节数最后独立核对。冷读或前缀变化会重做完整校验，不把损坏
档案修复为可读前缀。

`CommittedHistory` 与 `ReadonlyBridge.restoreCommitted` 共用 recorder 校验，
让冷读每条时钟只重算一次。缓存只含脱敏记录、恢复摘要和已校验时钟，
没有密钥、配对邀请或认证连接。实际恢复仍要求重新配对和应用确认。
调用方收到深拷贝，修改返回值不能改变后续读取依据。

进程内缓存按最近查询顺序保留，总上限为 16 个流、4096 条记录、
5 MiB 序列化日志字节；条数约束也限制解码对象数量。读取开始先移出缓存，
全部校验成功后才放回，失败的部分后缀不能成为下次读取依据。淘汰只影响
重复计算，不删除磁盘证据、修改游标或产生事件丢失。进程重启从冷读开始。

manifest 1.1/1.2/1.3 均支持；每流 4096 条/5 MiB 配额、同步 checkpoint 后 ack、
整批拒绝和明确缺口保持。当前仍重读全量文件字节，并对全量返回值深拷贝；
实时 SSE 仍有一秒等待，不代表有界持续历史或批量即时推送已完成。

2026-10-24 macOS/Node 22.22，使用
`node --import tsx scripts/measure-debug-throughput.mjs <output> 32 2048`：

| 校验方式 | events/s | ack P95 ms | 读取 P95 ms |
| --- | ---: | ---: | ---: |
| 旧全量重复校验 | 278.02 | 51.09 | 186.83 |
| 文件字节核验后复用前缀 | 723.68 | 44.21 | 51.19 |

两次均为 2048 条、64 次并发读取，发送方在下一批前等待当前读取。
新测量事件完整性通过，2048 条均满足校时预算；不是独立发送端的恒定到达率，
也不是 UI 延迟、真实 ArkTS Kit 或 1K events/s 十分钟认证。

未提交段、权限/链接、重算哈希后的语义错误、部分失败恢复、epoch 和流数淘汰。
