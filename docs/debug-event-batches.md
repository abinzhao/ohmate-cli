# 有界加密事件批次

桌面只读桥接可在加密 `ready` 中协商 `eventBatch: "events-v1"`。
对应 `connected/resumed` 回应必须回显同一值；未协商的客户端继续使用单事件帧。
批次格式为 `{type:"event-batch", version:"1", events:[...]}`，每批 1–64 条。
整个明文仍受会话的 `maxFrame` 限制，当前默认 65536 字节；条数上限不扩大字节预算。
传输仍为 loopback/HDC AEAD，无压缩或明文降级。

桌面按帧顺序校验全部事件的身份、通道、序号、重放和时钟。新事件整批预检，
任一失败不提交其有效前缀；保留窗口内的重复或恢复重放不再次写入日志。
接收队列仍为最多 8 帧、512 KiB，达到上限关闭连接。批次不绕过密钥的
65536 帧/短期过期边界，不自动重新配对或复用 nonce。

只协商批次的新流使用 manifest 1.3/`storage:"segments-v1"`；旧 manifest 1.1/1.2
文件保持可读。分段为不可变的 `<first>-<last>.seg`，含版本、范围、记录长度、
逐事件哈希链和整段哈希，单段最多 512 KiB。事件先二次脱敏；UI、DOM、
Storage 与 Console 文本仍只保存 memory-only 标记。

每批只刷盘一个分段，仍使用私有文件、文件 fsync、目录同步及独立 checkpoint
原子替换。checkpoint 同步成功、状态发布成功后才发送最后一条事件的累计 ack。
关闭会等待在途提交，关闭后不发布该批 ack。写入失败保留分段与旧 checkpoint，
历史读取和恢复拒绝未提交尾段，不猜测或删除证据。

manifest 1.3 保存双方握手，checkpoint 1.1 保存最多 24 个 epoch。
恢复须重新私有配对和应用确认。请求批次恢复只接受原 manifest 1.3 流；
不能给旧流添加分段或静默转换。未请求批次的客户端可逐事件续写 1.3 流，
此时每条独立提交。历史读取仍校验整个日志，包括范围外的尾记录、
协商范围、原始摘要和时钟重算；不会恢复认证。
每次重读全部文件字节并核对提交锚点，字节哈希完全相同的已校验前缀可复用；
新增记录继续重算，依据见 `debug-journal-reads.md`。

manifest 1.3 每流仍最多 4096 条/5 MiB，达到配额整批拒绝，报告新事件缺口。
显式同时协商 `retention:"rolling-v1"` 的新流采用 manifest 1.4，在同一配额内
淘汰最早整段。续写原 1.4 流必须再次协商该模式，不能转换旧档案；
具体提交锚点、缺口与公开分页见 [debug-retention.md](debug-retention.md)。
没有透明密钥轮换。批量提交或有界滚动都不证明工作台 1K events/s 持续十分钟目标。

2026-10-24 macOS/Node 22.22 的源代码加密 loopback 测量，使用
`node --import tsx scripts/measure-debug-throughput.mjs <output> 32 <count>`，
每 32 条启动一次并发全量读取，发送方在下一批前等待该读取：

| 事件 | 吞吐 events/s | ack P95 ms | 读取 P95 ms |
| --- | ---: | ---: | ---: |
| 512，旧逐事件基线 | 58.27 | 20.25 | 163.71 |
| 512，32 条一批 | 557.05 | 47.93 | 72.77 |
| 2048，32 条一批 | 278.02 | 51.09 | 186.83 |

扩大历史后读取成本仍增长。2048 条测量中 1696 条校准、352 条超过
时钟预算，未将超预算记录合并；两批测量完整性均通过。
这些数字是短时 Node 替身负载，不是真实 ArkTS Kit、硬件或 UI 延迟认证。
