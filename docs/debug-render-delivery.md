# 实时事件列表渲染

工作台收到 SSE 后立即检查独占提交游标。重复记录不调度渲染，序列缺口立即
结束跟随。已接受记录只保留最近 100 条，事件列表、计数与状态合并到一个
`requestAnimationFrame`；不增加事件内容队列。

暂停、故障和结束先显示尚未渲染的已接受记录，再显示对应状态。
刷新、会话或流选择、分页、离开调试视图取消旧帧。
帧回调检查视图代次、当前 EventSource 和帧身份，不能覆盖后来的页面或状态。
隐藏标签页可能延后浏览器帧，但记录与待调度帧仍保持上述界限。
磁盘日志、SSE ID、设备认证和时钟证据没有改变。

`verify-debug-workbench.mjs --browser --batch --render` 使用私有双 TTY、
Node 加密生产者、真实日志提交和 SSE。在浏览器中控制帧执行，
64 条连续到达先断言零次列表重建和一个待执行帧，执行帧后断言一次重建。
另验证重复游标、暂停、流选择、刷新、序列缺口、连接错误、结束和离页，
并重放已取消回调确认不会覆盖新状态。
缺口、错误、结束信号为浏览器注入；加密批次与 SSE 为真实网络。
旧实现首项实际失败为 `64 !== 0`，记录保留于 `m2-render-red-r1/`。

`--measure` 使用相同入口，记录每条事件创建时刻、实际 SSE 分发时刻、
列表替换后的 MutationObserver 时刻和随后的浏览器帧。
逐条断言提交序号、值和时间关系，保存原始 2048 个测量样本。
生产时间为同主机 UTC、1 ms 量化；浏览器使用
`performance.timeOrigin + performance.now()`。DOM 和下一帧观察均不证明
物理屏幕已绘制，不构成跨设备时钟校准。
吞吐区间为首次生产至最后一个样本的下一帧，自动化轮询另计。

`m2-render-measure-new-r2/`。此前测量保留，但其 `elapsedMs` 包含自动化轮询，
不与这两组时长混用。不同轮次的新版本 DOM P95 曾为 708.40 和 919.90 ms，
