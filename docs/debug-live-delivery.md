# 实时事件提交与推送

工作台事件 SSE 使用所属 BridgeHub 的提交通知。日志分段和独立 checkpoint
同步完成、桥接状态持久发布成功后，通知等待中的订阅重新读取日志；
通知不携带事件内容或认证信息，不能替代文件字节、哈希与提交锚点核验。
首次读取前注册订阅，读取与等待之间的提交保留一个待唤醒标记。

订阅按工作台会话与事件流隔离。流切换通知旧流和新流，旧流读完已提交记录后
结束；取消、断开、故障或服务关闭移除订阅和等待计时器。首次读取期间已断开的
响应不进入实时循环。状态持久化失败不发布成功通知。

每次传输合并一个已校验页面，默认 100 条、查询最大 256 条。
每条记录仍具有独立 `id` 和 `data`，HTTP API、`Last-Event-ID` 与独占游标不变。
响应背压等待 `drain` 或取消后再继续；等待期间只合并唤醒标记，不积压事件队列。
工作台最多 8 个 SSE 连接，磁盘仍限制每流 4096 条/5 MiB。

追平后的所属桥接提交立即唤醒。无通知时仍每秒安全重读一次，
检查外部进程写入、停止状态与静默损坏。没有所属桥接的历史会话保留原复核路径。
任务 SSE、设备认证、重新配对和时钟证据边界保持独立。

`scripts/measure-debug-live.mjs` 用 Node 加密生产者、实际状态持久发布和
HTTP SSE 消费者验证连续游标，最后完整读取日志确认数量和尾部。
使用同进程单调时钟测量生产至 SSE 消费延迟，结果不包含浏览器渲染。
