# 受控文本 Patch 与恢复

适用范围：OHMate 0.1.0 的 `workspace.patch`、
`workspace.recovery.inspect/restore`。这些工具处理工作空间中的公开文本，
不负责判断 ArkTS 编译正确性，也不代替工程、构建和设备验证。

## 请求与审批

```json
{
  "changes": [
    {
      "path": "src/main.ts",
      "oldHash": "<原文件 SHA-256>",
      "text": "<新文本>"
    },
    {
      "path": "src/new.ts",
      "oldHash": null,
      "text": "<新文件文本>"
    }
  ]
}
```

`text:null` 表示删除已有文件。所有路径必须精确、相对、规范化；不接受目录、
通配符、`..`、绝对路径或反斜杠。新文件父目录必须已存在。
最多 20 个目标、单文件 128 KiB、完整请求 256 KiB；Diff、旧文本和请求另有
900 KiB 的审查预算，落盘审批记录最多 1 MiB。超限在写工程文件前拒绝。

Runtime 的 R2 计划包含工具、参数、工程、风险、有效期、恢复方式及 `review`。
`review.files` 保存每个目标的操作、旧/新哈希、字节数和统一 Diff。
审批绑定实际工具 Schema、参数、工作空间内容、目标、版本和完整 `review`；
记录中的 Diff 被修改也会使审批失效。计划有效期十分钟，执行前单次消费。

读取旧文本和应用新文本均拒绝敏感内容。路径守卫拒绝敏感文件、依赖/构建/
产物目录、产品私有数据、符号链接祖先、硬链接和非普通文件。无法解码为
UTF-8 的内容、NUL 字节、重复目标和没有变化的请求也会被拒绝。

## 执行与证据

1. 校验全部旧内容与审查预算。
2. 在私有状态目录落盘恢复日志，记录全部旧文本、哈希、权限和拟应用文本。
3. 在目标文件同目录建立临时文件；写入并同步后，再核对原文件哈希。
4. 修改已有文件使用 `rename`，新建使用不覆盖已有目标的 `link`；
   删除前再次校验。保留已有文件权限。
5. 每个完成的目标即时核验新哈希，并追加 `patch.file.applied` 事件。
6. 记录最终状态，并通过独占创建写出证据快照；回执哈希对应该快照的实际字节。

| 结果 | 退出码 | 含义 |
| --- | --- | --- |
| `PATCH_APPLIED` | 0 | 全部目标写入且新哈希已核验 |
| `PATCH_ROLLED_BACK` | 6；取消时 130 | 执行未完成，本次已完成的写入已撤回 |
| `PATCH_RECOVERY_REQUIRED` | 6；取消时 130 | 至少一个已写目标出现冲突，撤回未完整完成 |
| `INPUT_INVALID` | 4 | 请求、路径、原内容或审查预算不符合合同 |

恢复日志是可演进状态；回执引用的是独立证据快照。执行恢复后，旧快照仍保留
最初的字节、哈希和状态。终端与 Web 读取同一计划、任务事件和回执。
网页的逐文件 Diff 使用文本节点渲染，不把代码内容解释为 HTML。

## 恢复

`workspace recovery inspect --journal-id <id>` 对比真实文件与原始/拟应用哈希，
逐文件给出 `original`、`applied` 或 `conflict`。不依赖日志中的完成计数来猜测
硬中断时的状态。

`workspace recovery restore --journal-id <id>` 只为仍匹配拟应用哈希的文件生成
反向 Patch；已恢复的文件跳过，冲突阻止自动恢复。恢复也必须审查独立 Diff
并确认计划，会产生自己的恢复日志和证据。恢复已删除文件时保留记录的权限。
不提供强制覆盖、目录删除或未经确认的自动恢复。

## Agent 范围

`context preview` 和 `agent run` 的 `writePaths`（CLI：`--write-paths`，
交互终端：`/write`）列出允许提出修改的精确路径。预览记录对应旧哈希；模型
提案必须同时匹配路径和旧哈希。默认范围为空，读取文件不自动授权写入。
新文件也须先选入范围，并受相同路径守卫约束。

模型提案创建独立待审批任务并结束本轮。人工执行后，下一轮重新预览会话关联
的实际回执；读取新文件也须重新加入 `files`。恢复和任务审批工具不开放给 Agent。
这条链已通过真实 pi SDK 与本地 SSE Producer 核验；付费云模型尚未认证。

## 原子性与验证边界

原子性针对单个文件；多文件使用日志与可核验撤回，Node API 不提供多文件事务。
OHMate 的锁仅协调本产品内的写入。外部进程在最后校验与文件系统调用之间
修改目录/文件的竞态，不能据此承诺完全排除；需要更强隔离时使用独立 checkout。
文件内容有 `fsync`，未承诺断电时目录元数据的完整持久性。

协作取消可以撤回；进程硬中断只提供后续显式检查和恢复。Windows/Linux 的
实际文件替换、链接与权限行为尚未在对应主机验收。当前真实执行平台为 macOS。
